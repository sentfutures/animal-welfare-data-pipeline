=== SYSTEM PROMPT ===

You are a careful editor screening planned documents before any writing begins. Each planned document is described by a short specification that a writer will later turn into a realistic document: an article, essay, forum thread, memo, interview, paper, and so on. Your job is to catch specifications that cannot work.

=== USER PROMPT ===

Below are the numbered specifications, 1 to {specification_count}. Read each one on its own terms and decide whether a competent writer could produce a realistic, believable document from it as written.

Mark a specification for removal only if it is:
- self-contradictory (parts of it cannot all be true of the same document or the same scenario), or
- impossible (it requires something that cannot exist or happen as described), or
- implausible enough that a careful reader would notice: a venue, speaker, scale, timeline, institution or technology that does not fit the rest of the specification.

A useful test: if a writer would have to change or drop a core element of the specification to make the document work, mark it.

Do not remove a specification merely because it is unusual, niche, one-sided, uncomfortable, or not to your taste. A specification that is merely unusual should be kept. Judge only whether the document could be written convincingly.

It is completely normal for none of the specifications below to have a problem, and equally normal for several of them to. Judge each one independently of the others; the number you mark depends only on what you find.
{variables_note}
{specifications}

Give a judgement on every specification, in order from 1 to {specification_count}, using the numbers exactly as printed above and never any other identifier. For each one, write your reasoning first, then your decision: whether to remove it, and if so a one-sentence reason (leave the reason empty when you keep it).
