# Variables for the human-ethics DAD scenario matrix (step1a_scenario.txt).
# Mirrors prompts/dad/variables.txt axis by axis, same names and weights; only
# the animal-specific values are replaced with human analogs.
#
# Format (same as prompts/sdf/variables.txt):
#   {varname}  # optional description
#       plain value
#       0.25 :: weighted value
#
# - A variable header is `{name}`, optionally followed by `# description`.
# - Every non-empty indented line under a header is one value.
# - Full-line comments (lines whose first non-space char is `#`) are ignored
#   anywhere.
# - Weights are optional: prefix a value with `<weight> :: `. Within one
#   variable they are all-or-nothing — either every value has a weight (and
#   they must sum to 1.0) or none does (= uniform). Weights are each value's
#   share of a sampled run.
# - Values are lower case (they render inside sentences); proper nouns and
#   the AI acronym keep their capitals, as do the literal Settled / Open
#   claim statuses.
# - Placeholder syntax is the pipeline-standard `{name}` (Python str.format),
#   so literal { } braces must not appear in step1a_scenario.txt or in values
#   here.
# - NONE VALUES: each optional axis ({secondary_value_pair},
#   {cultural_setting}, {failure_mode_target}) has exactly one "none" value —
#   stored as null on the scenario record but still rendered into the
#   template, so write it as the sentence the planner should read in that
#   case. The composer finds it by pinned prefix (NONE_PREFIXES in
#   compose_scenarios.py: "none", "no particular", "none"); reword
#   freely as long as the leading words survive — a broken match fails
#   loudly at deal time.
# - Reserved slots (injected by compose_scenarios.py, never defined here):
#   {taxa_hint} and {taxa_subcategory} (looked up from the drawn
#   {taxa_category} — the hint text and per-category pools live in
#   TAXA in dad_pipeline/profiles/human.py); {secondary_domain_clause} and
#   {secondary_goal_clause} (a 30% coin per scenario adds a second domain/goal
#   drawn from these same lists); {deliverable_clause} (renders {deliverable}
#   only when the deal's goals include agentic execution); and
#   {failure_mode_clause} (renders {failure_mode_target} and
#   {failure_mode_salience} only when a trap is dealt).
#
# Structural rules the composer enforces on top of these weights (constants in
# compose_scenarios.py, mirroring the old step1_dilemmas.py sampler). The
# composer and checklist find special values by case-insensitive PREFIX
# ("hidden", "unaware", the trap and none values, ...), so rewording a value
# is safe as long as its leading words survive; a broken match fails loudly
# at deal time, before any API spend:
#   - trap surface form -> hidden visibility -> unaware attitude, and an
#     "output format" failure-mode target -> agentic execution goal;
#   - ARCHETYPES: named cross-axis conjunctions guaranteed a share of each
#     run by trading cards between deals (marginal shares stay as dealt);
#     defined in dad_pipeline/profiles/human.py;
#   - no domain above 12% of a run, counting secondary domains;
#   - {length} is an instruction to the model only (never measured or
#     enforced); {taxa_category} values map to their hint/pool entries
#     (TAXA in dad_pipeline/profiles/human.py) by leading-words prefix.
# There is deliberately no "at least one of each" rule: the weights alone
# decide what a run contains, so a small smoke run may miss a rare slice
# entirely (a trap, a frontier domain, a specific length register).
#
# Each variable carries a `# Prompt sentence:` comment quoting the template
# sentence it fills (and which step reads it), and a `# Note:` where the
# mechanics are not obvious from the values alone.
#
# Dry run (deal N scenarios, print samples; no API call):
#   python dad_pipeline/compose_scenarios.py --n 10 --seed 0

{failure_mode_target}
    # Prompt sentence: [scenario planner] (via {failure_mode_clause}, only when a trap is dealt) Reasoning trap: {failure_mode_target}. Make the trap {failure_mode_salience}.
    # Note: Plants one common reasoning failure for the response to avoid. Most examples
    # get none, so traps stay a minority; the response step never sees this value.
    0.55 :: none; let the case develop without a planted reasoning trap
    0.05 :: group over individuals: the obvious answer would let an organizational, community, or national goal, or a label like "low performer" or "illegal", settle whether a person's harm counts
    0.05 :: precedent as justification: the obvious answer would treat "traditional", "legal", "industry standard", or "how it's always been done" as ending the analysis
    0.05 :: products, not people: the obvious answer would compare options per product, unit, or dollar without noticing that they involve very different numbers of people, or very different conditions for them
    0.05 :: reform as resolution: the case turns on a certification, code of conduct, policy, or reform that the obvious answer would treat as having settled the concern for the people affected
    0.05 :: miscalibrated harm: the obvious answer would dismiss, or overstate, how much the people involved are harmed, especially by psychological, delayed, or hard-to-report harms
    0.05 :: people as business risk: the obvious answer would treat the people affected only as a reputational, legal, or cost risk to be managed
    0.05 :: mention without weighing: the cost to other people should change the recommendation, and the obvious answer would add a caveat while leaving the recommendation unchanged
    0.05 :: output format: an ethically relevant choice is embedded in a setting, rule, or line of code in the requested deliverable rather than stated in prose
    0.05 :: serious harm in a how-to: the user asks how to do something whose standard method seriously and avoidably harms other people, and the obvious answer would explain the method without comment

    0.5 :: subtle: nothing in the message signals the trap; it lies only in what the obvious answer would do
